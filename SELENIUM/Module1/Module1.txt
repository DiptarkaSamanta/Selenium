1. WHAT & WHY SELENIUM
-------------------------------------------------------------------------------
What is Selenium?
  Selenium is a widely-used open-source automated testing suite specifically 
  designed for automating web applications across different web browsers and 
  operating systems.

Why Selenium?
  • Open-Source & Free: No licensing fees; supported by an active global community.
  • Multi-Language Support: Allows writing test scripts in Python, Java, C#, 
    JavaScript, Ruby, and Kotlin.
  • Multi-Browser Compatibility: Supports Chrome, Firefox, Edge, Safari, Opera.
  • Multi-Platform Support: Runs on Windows, macOS, and Linux.
  • Seamless Integrations: Integrates easily with testing frameworks (pytest, 
    unittest, TestNG, JUnit), CI/CD pipelines (Jenkins, GitHub Actions), and Docker.
  • Rich Ecosystem: Supported by helper libraries like webdriver-manager and 
    extensive community resources.

-------------------------------------------------------------------------------
2. SELENIUM IDE & SELENIUM RC
-------------------------------------------------------------------------------
Selenium IDE (Integrated Development Environment):
  • Concept: A browser extension (Chrome, Firefox, Edge) providing a record-and-
    playback interface.
  • Best Used For: Rapid test prototyping, quick bug reproduction, and exporting 
    recorded scripts to programming languages.
  • Limitations: Lacks support for complex conditional logic, data-driven testing, 
    dynamic wait handling, and high-volume parallel execution.

Selenium RC (Remote Control / Selenium 1):
  • Concept: The original flagship component of Selenium before WebDriver.
  • Architecture: Relied on a middleman "Selenium RC Server" which injected 
    JavaScript into the browser to automate page interactions.
  • Limitations: Slower performance, complex server architecture, and subject 
    to browser Same-Origin Policy (SOP) security restrictions.
  • Current Status: Deprecated and obsolete; superseded by Selenium WebDriver.

-------------------------------------------------------------------------------
3. SELENIUM WEBDRIVER
-------------------------------------------------------------------------------
What is Selenium WebDriver?
  Selenium WebDriver (introduced in Selenium 2 and standardized in W3C with 
  Selenium 4) directly controls web browsers by communicating natively with 
  their browser engine drivers without injecting JavaScript.

Architecture & Workflow:
  1. Test Script (Python/Java/C#): Sends test commands via client bindings.
  2. W3C WebDriver Protocol: Standardized HTTP/JSON API communication.
  3. Browser Driver (e.g., ChromeDriver, GeckoDriver): Translates commands into 
     native browser instructions.
  4. Browser (Chrome, Firefox, etc.): Executes the actions natively.

Key Features & Advantages:
  • Direct Native Browser Control: Simulates real user interactions accurately.
  • Advanced Controls: Handles dynamic web elements, alerts, frames, multi-window 
    tabs, complex user actions (drag-and-drop), and explicit/implicit waits.
  • No Middleman Server Needed: Directly launches and controls browser processes.

-------------------------------------------------------------------------------
4. SELENIUM GRID
-------------------------------------------------------------------------------
What is Selenium Grid?
  Selenium Grid is a distributed testing execution environment that enables 
  running test scripts in parallel across multiple machines, operating systems, 
  and browsers simultaneously.

Key Benefits:
  • Parallel Execution: Drastically cuts down overall test suite execution time.
  • Cross-Browser & Multi-OS Matrix: Runs tests on combinations like Windows/Chrome, 
    macOS/Safari, and Linux/Firefox at the same time.

Architecture Overview:
  • Grid 3 (Hub & Node Architecture):
      - Hub: Central master server that receives test requests and routes them 
        to matching Nodes based on desired browser capabilities.
      - Node: Registered worker machines that execute tests on specific browsers/OS.
  • Grid 4 (Modern Distributed Architecture):
      - Componentized microservices architecture (Router, Distributor, Session 
        Queue, Sessions Map, Node, Event Bus).
      - Built-in support for Docker containers, Standalone mode, and Cloud Grids.
