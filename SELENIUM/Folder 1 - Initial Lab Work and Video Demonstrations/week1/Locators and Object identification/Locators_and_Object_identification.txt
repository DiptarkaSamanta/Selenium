1. DISCUSSION ON CHALLENGES AND COMPLEX WEB ELEMENT LOCATOR IDENTIFICATION
-------------------------------------------------------------------------------
Identifying web elements reliably is the foundation of automated software testing. 
In modern web applications (React, Angular, Vue, AJAX-heavy SPAs), object identification 
faces several key challenges:

Key Challenges:
  • Dynamic IDs & Attributes: Frameworks generate auto-generated IDs that change 
    on every page reload (e.g., `id="input_83921"` -> `id="input_91823"`).
  • Non-Unique Attributes: Elements sharing identical class names, names, or tags.
  • Dynamically Loaded Content: Elements added to DOM asynchronously (AJAX/Fetch),
    requiring wait strategies (Explicit Waits).
  • Hidden Elements / Shadow DOM / Iframes: Elements nested inside Shadow Roots 
    or iFrames that cannot be found by standard top-level DOM queries.
  • Complex Layout Structure: Deeply nested HTML layouts requiring resilient 
    traversal paths rather than absolute/fragile XPaths.

Best Practices for Robust Locator Selection:
  1. Priority order: ID > Name > CSS Selector > Unique XPath > Link Text.
  2. Avoid auto-generated or numeric-suffix IDs/classes.
  3. Use CSS substring matchers (wildcards) for dynamic attributes.
  4. Prefer relative paths over absolute DOM hierarchy paths.

2. UNDERSTANDING ELEMENTS, FIND ELEMENT BY ID AND NAME
-------------------------------------------------------------------------------
Web elements represent DOM (Document Object Model) nodes on a webpage. In Selenium,
`driver.find_element(By, value)` returns a single `WebElement` instance.

A. Locating by ID (`By.ID`):
   • ID is generally the fastest and most reliable locator strategy because HTML 
     standards mandate unique IDs within a page.
   • Example:
     ```python
     element = driver.find_element(By.ID, "username")
     element.send_keys("testuser")
     ```

B. Locating by Name (`By.NAME`):
   • Used primarily with HTML form inputs, buttons, and textareas.
   • Example:
     ```python
     element = driver.find_element(By.NAME, "email")
     element.send_keys("user@example.com")
     ```

-------------------------------------------------------------------------------
3. BY TAG NAME, LINK TEXT, AND CLASS NAME
-------------------------------------------------------------------------------

A. Locating by Tag Name (`By.TAG_NAME`):
   • Locates elements based on their HTML tag (e.g., `h1`, `input`, `a`, `button`).
   • Useful when fetching headers, images, or forms.
   • Example:
     ```python
     heading = driver.find_element(By.TAG_NAME, "h1")
     print(heading.text)
     ```

B. Locating by Link Text (`By.LINK_TEXT` & `By.PARTIAL_LINK_TEXT`):
   • `By.LINK_TEXT`: Matches the exact visible text of an anchor element (`<a>`).
   • `By.PARTIAL_LINK_TEXT`: Matches a substring of the visible text.
   • Examples:
     ```python
     # Exact match
     driver.find_element(By.LINK_TEXT, "Software Testing").click()

     # Partial match
     driver.find_element(By.PARTIAL_LINK_TEXT, "Testing").click()
     ```

C. Locating by Class Name (`By.CLASS_NAME`):
   • Locates elements based on the HTML `class` attribute.
   • Note: If an element has multiple space-separated classes (e.g. `class="btn btn-primary"`),
     `By.CLASS_NAME` accepts only a single class name (`btn-primary`), NOT space-separated compound classes.
   • Example:
     ```python
     btn = driver.find_element(By.CLASS_NAME, "btn-primary")
     btn.click()
     ```

-------------------------------------------------------------------------------
4. FIND LIST OF ELEMENTS (`find_elements`)
-------------------------------------------------------------------------------
While `find_element()` returns the first matching `WebElement` (or raises `NoSuchElementException`),
`find_elements()` returns a Python `list` of all matching `WebElement` objects.

Key Characteristics:
  • If matching elements are found: Returns `[WebElement1, WebElement2, ...]`.
  • If no elements match: Returns an empty list `[]` (Does NOT throw an exception!).
  • Ideal for verifying element existence, counting items, or iterating over rows/links/options.

Examples:
  ```python
  # Count total links on a page
  all_links = driver.find_elements(By.TAG_NAME, "a")
  print("Total links:", len(all_links))

  # Extract text from all list items
  items = driver.find_elements(By.CLASS_NAME, "list-item")
  for item in items:
      print("Item:", item.text)
  ```

5. BY CSS, USING WILDCARDS WITH CSS SELECTORS, CHILD NODES
-------------------------------------------------------------------------------
CSS Selectors provide high-speed, powerful, and flexible element identification.

A. Basic CSS Selectors (`By.CSS_SELECTOR`):
   • ID selector: `#element_id`
   • Class selector: `.class_name`
   • Tag & Attribute: `input[type='text']` or `button[name='submit']`

B. CSS Wildcards / Pattern Matching (Handling Dynamic Attributes):
   • Starts with (`^=`): Matches attribute values starting with a specific string.
     `driver.find_element(By.CSS_SELECTOR, "input[id^='user_']")`
   • Ends with (`$=`): Matches attribute values ending with a specific string.
     `driver.find_element(By.CSS_SELECTOR, "input[id$='_name']")`
   • Contains (`*=`): Matches attribute values containing a substring anywhere.
     `driver.find_element(By.CSS_SELECTOR, "button[class*='submit-btn']")`

C. Traversing Child Nodes and Siblings in CSS:
   • Direct Child (`>`): Targets an element that is an immediate child of a parent.
     `div.form-group > input`
   • Descendant (Space ` `): Targets an element anywhere inside a parent container.
     `form#login-form input`
   • Pseudo-class positional matchers:
     - First child: `ul#nav-menu > li:first-child`
     - Last child: `ul#nav-menu > li:last-child`
     - Nth child: `table.data-table tr:nth-child(3)`
   • Adjacent Sibling (`+`): Targets the immediate next sibling element.
     `label[for='email'] + input`
   • General Sibling (`~`): Targets any subsequent sibling element.
     `h2 ~ p`
