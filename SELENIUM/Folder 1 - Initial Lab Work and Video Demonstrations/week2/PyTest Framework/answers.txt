--------------------------------------------------------------------------------
1. INTRODUCTION OF PYTEST
--------------------------------------------------------------------------------
PyTest is a mature, full-featured Python testing framework that makes it easy to 
write small, readable tests, and scales to support complex functional testing for 
applications and libraries.

Key Features & Advantages over `unittest`:
1. Reduced Boilerplate:
   - No need to create classes inheriting from base test classes or wrap assertions 
     in special method calls (`self.assertEqual`). Standard Python `assert` 
     statements are used.
2. Powerful Fixture Architecture:
   - PyTest fixtures are explicit, modular, scalable, and reusable across tests, 
     modules, and sessions via dependency injection.
3. Parameterization:
   - Built-in support for running a test function multiple times with different sets 
     of input data using `@pytest.mark.parametrize`.
4. Rich Plugin Ecosystem:
   - Extensible via thousands of plugins such as `pytest-html`, `pytest-xdist` 
     (parallel execution), `pytest-cov` (code coverage), and `pytest-rerunfailures`.
5. Intelligent Assertion Introspection:
   - Provides detailed context and variable inspection when standard `assert` 
     statements fail.


--------------------------------------------------------------------------------
2. INSTALLING PYTEST AND NAMING CONVENTIONS
--------------------------------------------------------------------------------
Installation:
To install PyTest using `pip`, execute:
```bash
pip install pytest
```

To verify installation:
```bash
pytest --version
```

PyTest Naming Conventions (Crucial for Automatic Test Discovery):
When you run `pytest` from the terminal, PyTest automatically scans the directory 
and subdirectories following these discovery rules:

1. Test Files:
   - File names MUST start with `test_` (e.g., `test_login.py`) 
     OR end with `_test.py` (e.g., `login_test.py`).
2. Test Classes:
   - Class names MUST start with `Test` (e.g., `TestAdminLogin`).
   - The class MUST NOT have an `__init__` constructor method.
3. Test Functions / Methods:
   - Function or method names MUST start with `test_` (e.g., `test_valid_credentials()`).


--------------------------------------------------------------------------------
3. TEST FILES, TEST METHODS AND ASSERTIONS
--------------------------------------------------------------------------------
In PyTest, tests are plain functions (or methods inside a `Test` class) that use 
standard Python `assert` statements.

Example PyTest File (`test_sample.py`):

```python
import pytest
from selenium import webdriver

def test_google_title():
    driver = webdriver.Chrome()
    driver.get("https://www.google.com")
    
    # Standard Python assert statement with detailed inspection on failure
    assert driver.title == "Google", f"Expected 'Google' but got '{driver.title}'"
    
    driver.quit()

def test_string_containment():
    heading = "Welcome to Selenium Testing"
    assert "Selenium" in heading

def test_exception_handling():
    # Verifying that an exception is raised
    with pytest.raises(ZeroDivisionError):
        res = 1 / 0
```

Assertion Comparison:
- Unittest: `self.assertEqual(a, b)`
- PyTest: `assert a == b`


--------------------------------------------------------------------------------
4. SUBSETS AND TESTSUITES
--------------------------------------------------------------------------------
PyTest allows selecting specific subsets of tests to run without modifying code.

1. Running Specific Test Files:
   ```bash
   pytest test_login.py test_signup.py
   ```

2. Running Tests by Keyword Matching (`-k` flag):
   - Executes tests whose name matches a given substring or boolean expression.
   ```bash
   pytest -k "login"
   pytest -k "login or admin"
   pytest -k "not regression"
   ```

3. Running Tests using Custom Markers (`@pytest.mark`):
   - Mark tests with decorators for logical categorization (e.g., smoke, regression).

   ```python
   import pytest

   @pytest.mark.smoke
   def test_smoke_check():
       assert True

   @pytest.mark.regression
   def test_full_regression():
       assert True
   ```

   Execution by marker (`-m` flag):
   ```bash
   pytest -m smoke
   pytest -m "smoke and not slow"
   ```

   Note: Register custom markers in `pytest.ini` to avoid warnings:
   ```ini
   [pytest]
   markers =
       smoke: mark test as smoke test
       regression: mark test as regression test
   ```

5. FIXTURES AND CONFTEST.PY
--------------------------------------------------------------------------------
Fixtures are functions that run before (and optionally after) tests to set up 
preconditions and tear down postconditions.

Declaring a Fixture:
Use `@pytest.fixture` decorator.

Yield Pattern for Teardown:
Code BEFORE `yield` runs during setup; code AFTER `yield` runs during teardown.

Fixture Scopes:
- `function` (default): Runs once per test function.
- `class`: Runs once per test class.
- `module`: Runs once per module (.py file).
- `session`: Runs once per test run session.

Role of `conftest.py`:
- `conftest.py` is a special file used to share fixtures across multiple test files.
- Tests automatically discover fixtures defined in `conftest.py` without needing to 
  explicitly import them.

Example `conftest.py`:

```python
import pytest
from selenium import webdriver

@pytest.fixture(scope="function")
def driver():
    # Setup: Initialize Chrome driver
    print("\n[SETUP] Launching Chrome Browser...")
    driver_instance = webdriver.Chrome()
    driver_instance.maximize_window()
    driver_instance.implicitly_wait(10)
    
    yield driver_instance  # Provide fixture value to test
    
    # Teardown: Quit driver
    print("\n[TEARDOWN] Quitting Chrome Browser...")
    driver_instance.quit()
```

Example Usage in Test File (`test_search.py`):

```python
def test_search_example(driver):
    driver.get("https://www.google.com")
    assert "Google" in driver.title
```

6. PYTEST- FEATURES
--------------------------------------------------------------------------------
1. Parameterization (`@pytest.mark.parametrize`):
   - Pass multiple datasets to a single test function to perform Data-Driven Testing.

   ```python
   import pytest

   @pytest.mark.parametrize("username, password, expected", [
       ("valid_user", "correct_pass", True),
       ("invalid_user", "correct_pass", False),
       ("valid_user", "wrong_pass", False),
   ])
   def test_login_credentials(username, password, expected):
       print(f"Testing login for {username}")
       # Simulate authentication logic
       result = (username == "valid_user" and password == "correct_pass")
       assert result == expected
   ```

2. Skipping Tests & Expected Failures:
   - `@pytest.mark.skip(reason="...")`: Unconditionally skip test.
   - `@pytest.mark.skipif(condition, reason="...")`: Skip conditionally.
   - `@pytest.mark.xfail`: Mark test as expected to fail.

3. Command-line Custom Options (`pytest_addoption`):
   - Pass custom parameters via CLI (e.g., `--browser chrome` or `--env staging`).


--------------------------------------------------------------------------------
7. RUN MULTIPLE_TEST_CASE
--------------------------------------------------------------------------------
Executing multiple test cases across directories and files:

1. Run all tests in a project directory:
   ```bash
   pytest
   ```

2. Run all tests in a specific folder:
   ```bash
   pytest tests/
   ```

3. Run multiple specific test files:
   ```bash
   pytest tests/test_login.py tests/test_cart.py
   ```

4. Useful CLI Flags:
   - `-v` / `--verbose`: Detailed output showing each test method name and status.
   - `-s`: Disables output capture (allows `print()` statements to display in console).
   - `--tb=short`: Shortened traceback format on failure.
   - `-n <num>`: Runs tests in parallel across multiple CPU cores (requires `pytest-xdist`).

8. MOVING SELENIUM TEST TO PYTEST
--------------------------------------------------------------------------------
Converting standard unittest scripts to PyTest improves readability and modularity.

Before (Unittest Style):
```python
import unittest
from selenium import webdriver

class UnittestSelenium(unittest.TestCase):
    def setUp(self):
        self.driver = webdriver.Chrome()

    def test_title(self):
        self.driver.get("https://example.com")
        self.assertEqual(self.driver.title, "Example Domain")

    def tearDown(self):
        self.driver.quit()
```

After (PyTest Style):
```python
# conftest.py contains driver fixture
import pytest
from selenium import webdriver

@pytest.fixture
def setup_driver():
    driver = webdriver.Chrome()
    yield driver
    driver.quit()

# test_example.py
def test_title(setup_driver):
    driver = setup_driver
    driver.get("https://example.com")
    assert driver.title == "Example Domain"
```

Key Refactoring Steps:
1. Replace `unittest.TestCase` inheritance with standard functions.
2. Move setup/teardown logic into `@pytest.fixture` yield functions.
3. Replace `self.assertEqual(...)` with plain `assert ...`.
4. Use dependency injection to pass fixtures into test arguments.

9. INSTALL PYTEST HTML PLUGIN AND GENERATE HTML REPORTS
--------------------------------------------------------------------------------
The `pytest-html` plugin generates beautiful, self-contained HTML test execution 
reports.

Installation:
```bash
pip install pytest-html
```

Generating HTML Reports:
Execute pytest with `--html` option specifying report file path:
```bash
pytest --html=reports/report.html --self-contained-html
```

Options:
- `--html=report.html`: Path where HTML report will be saved.
- `--self-contained-html`: Embeds CSS, images, and Javascript directly into a single 
  standalone HTML file, making it easy to share via email or CI/CD artifacts.

Customizing Reports in `conftest.py`:
- You can add environment details (Browser, OS, Tester Name) and attach screenshot 
  thumbnails on test failure using PyTest hooks (`pytest_html_results_table_header`, 
  `pytest_runtest_makereport`).
